CVE-2026-123007 and CVE-2026-123633.

## Release-note review

| Area | Finding | Effect on Bittern |
| --- | --- | --- |
| Live view | The release adds a troubleshooting note that disabling browser V8 optimisations can cause live view problems. The go2rtc security changes below also touch stream sources. | No renderer or page change in this pin bump. The existing live view design remains valid. |
| Config schema | No config key was removed or renamed. `ffmpeg.path` now rejects spaces, quotes and shell characters and must be a version alias or a plain absolute path. go2rtc `ffmpeg` and `ngrok` keys are restricted unless arbitrary exec is enabled. | Product config does not set `ffmpeg.path`, `go2rtc.ffmpeg` or `go2rtc.ngrok`, so the rendered config needs no change. |
| Compose file | The release changes no upstream compose file. Bittern's compose file is generated locally and only its image reference changed. | No compose template or structure change. |
| go2rtc block | Frigate still bundles go2rtc 1.9.14; the Dockerfile pin did not change in the compare. Stream sources containing `${VAR:default}` are now restricted unless `GO2RTC_ALLOW_ARBITRARY_EXEC=true`, because the default can name an `exec:` source. The API and startup also reject changed `go2rtc.ffmpeg` and `go2rtc.ngrok` settings by default. | The renderer emits no go2rtc block today. Future live view work must use `{FRIGATE_*}` substitution, not `${...}`, and must not depend on custom go2rtc ffmpeg or ngrok options. |
| API | No endpoint this project uses was removed or renamed. The MJPEG feed description changed, and the chat watch stop now checks ownership. The `/api/version`, `/api/stats`, `/api/config` and `latest.jpg` paths are unchanged. | No agent or UI change required. Chat and VLM are unused. |
| nginx and VOD | nginx moves from 1.27.4 to 1.30.7. The VOD HLS block drops `secure_token`, sets HLS version 6 and preserves playlist query arguments. | The product does not use the VOD HLS path yet. Recorded playback work must test this path against the new image. |
| Docs | The PTZ camera recommendation table was removed and replaced with the ONVIF and CCTV databases. | No product effect. The ONVIF limitation and OQ-39 remain. |

No release-note item required stopping for a removed or renamed config key.

## What remains unproven

- The full QEMU firstboot and apply path against 0.18.3, because the POC installer payload hits the
  existing trust-anchor failure before Frigate starts. The fixture smoke proves the image, config
  check, start, API login and snapshot; it does not prove first boot or the update transaction.
- The hardware compose file, which still needs a real `/dev/dri` and `/dev/bus/usb` host.
- Config and database migration from 0.18.2. The 0.18.3 compare shows no config schema or database
  migration change, but only a real firstboot or upgrade run can prove it.
- The SBOM. It is still generated at bundle-build time and is not claimed here.

The firstboot trust-anchor failure needs its own harness fix before the full apply path can be
reported green against this pin.
